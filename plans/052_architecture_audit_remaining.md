## §2 B：rolling-upload 2d 的执行清单（下一步候选）

**目标**：`rolling-upload` 的建稿/追加不再直接调用 `uploadPlainRaw` / `appendGroupRaw`，
只通过 `UploadTarget`；与 live-pump 共用「建稿 → append → 重试 → 幂等」的唯一驱动。
行为对拍优先：argv、换线顺序、分 P 回读、可见性转换一项不能漂。

**先写测试再改**：

1. 用现有 golden argv 断言锁定 rolling 的建稿/追加参数；
2. 给 `UploadTarget` 加一个只记录调用的假 target，证明 rolling 不再触达旧函数；
3. 对拍 `confirmed` 写回与 sidecar 语义：成功才写、失败不写、`confirmed` 不重复；
4. 覆盖「追加结果不确定」：不自动重试，sidecar 留下可人工核对的证据；
5. 覆盖停止信号：等待限流冷却时可中断，不把不可逆请求排到停止之后。

**改动边界**：

- 只改 `app/src/rolling-upload.ts` 及其装配点；
- 不碰 `live-pump`、不改 `proc-queue` schema、不改生产任务字段；
- 保留一个发布周期的兼容注入（`uploadPlainRaw`/`appendGroupRaw` 仍可传入），
  调用归零后再删。

**验收**：

- `pnpm typecheck`、全量 `pnpm test`、`pnpm arch:check` 绿；
- 撤掉 target 接线时新测试红、复原绿（PR 正文附两段真实输出）；
- 真实 B 站上传测试分段 **≥120 秒**；短段仅用于 mock/单测；
- 真实跑至少覆盖：建稿、追加、限流冷却、确认后 cleanup、sidecar 回写；
- 失败时不删除源文件；成功确认前不 cleanup。
